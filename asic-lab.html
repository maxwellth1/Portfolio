Lab 06

FIR Filter

This lab focuses on a controller that sequences multi-cycle datapath operations. The flowchart lays out the control path through load, wait, shift, arithmetic, accumulation, and error-handling states. The RTL diagrams show the controller's next-state and output logic, plus the magnitude block's input/output interface. Lab 07 · APB

APB UART SoC Peripheral

Lab 7 extends the UART receiver into a memory-mapped System-on-Chip peripheral using the Advanced Peripheral Bus (APB). The subordinate interface exposes UART data, status, and configuration through addressable registers. The design also connects the APB interface to the receiver block, allowing software to configure the bit period and data width, poll for received data, and read the data buffer.

The interface follows the lab's register map: data-ready status, error status, bit-period configuration, data-size configuration, and the received-data buffer. The receiver's handshake clears the available-data indication when software reads the buffered payload.

Lab 08 · AHB

Pipelined FIR Filter Peripheral

Lab 8 connects the FIR filter to an Advanced High-performance Bus (AHB) subordinate interface. Unlike APB, AHB overlaps the address phase of one transfer with the data phase of the previous transfer. The subordinate therefore has to account for pipelined reads and writes, register the read-data path, align data according to transfer size, and handle read-after-write hazards.

The coefficient loader is a small state machine that sequences coefficient transfer from the AHB-visible registers into the FIR filter. It indexes the coefficient number, asserts the load control, and signals when the loading operation is complete. The AHB register map also exposes filter status, result, new sample, and coefficient registers.

Course Design Lab · CDL

Systolic Array Matrix-Multiplication Accelerator

The CDL project is an AHB-connected hardware accelerator for matrix multiplication, intended to support fully connected neural-network inference. The project specification describes an accelerator that accepts matrices up to 8×8, stores weights in a weight-stationary systolic array, accumulates partial sums, adds bias, and applies an activation function. The diagrams below show the top-level organization and the internal processing structures.

At each processing element, an input value is multiplied by a stored weight and added to the incoming partial sum. Registers between processing elements provide pipelining as inputs move across the array and partial sums move through it. The surrounding design handles weight loading, buffering, bus transactions, bias addition, and activation of the resulting values.
